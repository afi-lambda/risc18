# P3 brief: `Core7` — the seven-stage restart core

Frozen target: `docs/ISA.md` §7. Stages, latencies, bubble counts and the retire
interface are normative there; this brief is the work order, not a second spec.

## Deliverable

`src/risc18/core7.py` — a `Core7` elaboratable with the **same ports as `Core`**
(`i_rst`, `o_pc`, `o_retire`, `o_retire_pc`, `o_retire_we`, `o_retire_rd`,
`o_retire_value`, `o_halt`) so the golden model and the existing tests apply unchanged.

Plus `tests/test_core7.py` and a `Core7Top` in `tops.py` for routed builds.

## Non-negotiables

1. **Encodings do not change.** `isa.py` is frozen; do not touch `isa.py`, `golden.py`,
   `asm.py`, or any existing test. If a test fails, the core is wrong, not the test.
2. **Every existing test must pass unchanged** (317 today). The new core is a second
   implementation of the same ISA, not a new ISA.
3. **Stages are exactly F · IQ · D · R · X · M · W.** Do not add a stage to hide a
   timing miss, and do not move the register-file read into X (83.4 MHz) or read the
   EBR in R (111.53 MHz).
4. **Memory is latency 2 by edge contract** (§7.1). X presents the address, the block
   samples at the X/M edge, the output is captured at the M/W edge, W exposes the word.
5. **Bubble counts are as specified** (§7.2): ALU/MUL free at any distance, load-use
   exactly one bubble. The M→X input bypass is the mechanism that makes ALU distance 1
   free; if it costs more than the X budget allows, take the one-bubble fallback and
   report it — do not silently widen the pipeline.

## Tests the new core must carry

- the full existing suite, unchanged
- a cycle-count test per stage: `F` fill, taken-branch recovery = 2, not-taken = 0
- a load-use test at distance 1 (1 bubble) and distance 2 (0 bubbles)
- an ALU dependency at distance 1 and 2 (0 bubbles each), through the M→X and X→R bypass
- a MUL dependency at distance 1 and 2 (0 bubbles), with the product registered
- retire counts and values identical to `Core` on the same programs, including the
  M10/M11 workloads already under `tests/`

## Gates

| gate | criterion |
|---|---|
| SIM | `pytest -q` 100 %, existing suite unchanged plus the new tests |
| trace | `o_retire*` identical to `Core` on every program in `tests/` |
| PnR | `Core7Top` seeds 1/2/3/7, worst seed >= 120 MHz |
| HIL | on the board via `tools/hil_status.py`, then MIPS on the same counted loop as the 5-stage baseline (45.5 MIPS) |

P4 signs off on **MIPS, not MHz**: 120 MHz at CPI 1.5 is 80 MIPS. A core that reaches
120 MHz and measures 40 MIPS has failed the stage.

## Stop conditions

- a stage misses 8.33 ns after routing: report the stage and the path, do not restructure
  without the measured number
- the existing suite cannot be made to pass without editing it: stop and report
- any change that would need an ISA change: stop and report; the ISA is frozen

The routed `Core7Top` numbers (per seed), the CPI on the counted loop, the diff against
`Core`'s retire trace, and `docs/metrics/NOTES.md` updated with a `## Core7` section.
